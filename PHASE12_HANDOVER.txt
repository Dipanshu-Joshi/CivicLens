4. IMPLEMENTATION COMPLETED
---------------------------

4.1 A - Database / Supabase
- Static Flyway inventory reviewed: V1 through V13 all exist in source.
- Correct detail: V8__phase5_image_analysis.sql EXISTS. The originally planned
  V8__super_admin_seed.sql was never created because the first super admin is
  bootstrapped from local environment values. A hosted Flyway run should show
  13 successful rows, not 12.
- No new Flyway migration was added.
- H2 schema/test double continues to be used for automated tests; it is NOT
  evidence of real PostgreSQL/PostGIS behavior.
- scripts/phase12-hosted-preflight.ps1 validates the source inventory and
  reports exact hosted blockers without printing values or contacting networks.

4.2 B - Object storage
Existing secure upload controls were retained and strengthened with local tests:
- Cross-user discard now explicitly returns 403.
- Pending upload is rolled back if presigning fails.
- Missing and oversized objects are rejected.
- Presigned PUT/GET TTLs are asserted.
- Storage failure during AI/image flow does not lose complaint data.
- Ownership checks are enforced.
Hosted S3 HeadBucket, signed transfer, and private-bucket checks are BLOCKED.

4.3 C - Notifications / password reset email
- Added spring-boot-starter-mail.
- Added PasswordResetEmailChannel using ObjectProvider<JavaMailSender> so an
  unconfigured mail provider does not break startup.
- Email is disabled unless CIVICSENSE_MAIL_ENABLED=true and all SMTP values are
  supplied.
- Existing outbox event auth.password_reset_requested is routed to SMTP.
- Deterministic Message-ID based on the outbox event provides best-effort
  provider-side dedupe.
- Raw reset token is never logged. It exists only in the outbox payload and the
  outbound email body.
- Provider exceptions are sanitised to IllegalStateException("Password-reset
  email delivery failed"); provider text is never persisted to last_error or
  logged.
- Fixed terminal FAILED outbox rows: null nextAttemptAt is no longer treated as
  due for terminal failures, while new PENDING rows remain immediately due.
- Local fake-transport tests cover success, failure, retry, and no-duplicate
  behavior.
- Real SMTP delivery is BLOCKED until an operator supplies a provider.

4.4 D - Distributed infrastructure
- Evaluated Redis/shared rate limiting.
- Decision: DO NOT implement. No Redis dependency, service, CLI, config, or
  shared store exists. Deployment remains single-process.
- Existing in-memory Bucket4j behavior, limits, 429 responses, and Retry-After
  headers are preserved.
- Cross-instance testing is BLOCKED/not applicable without a shared store and a
  scale-out decision.

4.5 E - Observability
- Boot 4.2 built-in structured ECS JSON console logging enabled with:
    logging.structured.format.console: ecs
  `json` is invalid in Boot 4.2 and was not used.
- Added global correlation components under:
    backend/src/main/java/com/civicsense/observability/
    - CorrelationId.java
    - CorrelationIdFilter.java
    - MdcTaskDecorator.java
- X-Correlation-Id is generated or echoed at the request boundary, exposed via
  CORS, and propagated into MDC, async workers, scheduled cleanup, error bodies,
  health responses, and audit rows.
- Centralised previously scattered UUID.randomUUID() sites.
- Structured logging, MDC propagation, correlation integration, and redaction
  behavior are covered by tests.
- Log aggregation and alerting remain operator-provided; no monitoring stack was
  added.

4.6 F - Security / authz
- Authorization/isolation regression tests remain green.
- PostgreSQL RLS was evaluated but NOT enabled. Reason: no least-privilege DB
  role, no real PostgreSQL integration matrix, and background delivery/retention
  REQUIRES_NEW flows could break. Application-layer RBAC, ownership checks, and
  department-scoped queries remain authoritative.
- Argon2id decision was superseded by owner-directed implementation:
    - Added UpgradingPasswordEncoder with prefix {argon2id}.
    - New and reset passwords are Argon2id.
    - Legacy BCrypt hashes still verify.
    - Successful login transparently rehashes legacy passwords.
    - No schema migration required because password_hash is varchar(255).
- Bouncy Castle was initially added at 1.84; dependency audit found critical and
  high advisories. Upgraded to 1.85; final audit is clean.

4.7 G - Production-like no-Docker verification
